# Skip S3 Cleanup Annotation

## Overview

The `aws.managed.openshift.io/skip-s3-cleanup` annotation allows you to skip S3 bucket cleanup during AccountClaim finalization. This is useful when:

- S3 bucket cleanup is taking too long and blocking other operations
- S3 cleanup will be handled externally (e.g., by another process or manual intervention)
- You want to preserve S3 data for debugging or migration purposes

## Performance Impact

S3 bucket cleanup can significantly slow down the operator when there are many objects to delete. All AWS cleanup operations run in parallel, but when S3 cleanup is stuck deleting thousands/millions of objects, it blocks the entire finalization process and prevents other AccountClaims from being processed efficiently.

By skipping S3 cleanup, the operator can:
- Complete AccountClaim finalization faster
- Free up operator capacity to process other reconciliations
- Avoid timeouts during cleanup operations

## Usage

### Adding the Annotation

To skip S3 cleanup for a specific AccountClaim, add the annotation when creating the claim or patch an existing one:

#### Creating a new AccountClaim with the annotation

```yaml
apiVersion: aws.managed.openshift.io/v1alpha1
kind: AccountClaim
metadata:
  name: my-account-claim
  namespace: aws-account-operator
  annotations:
    aws.managed.openshift.io/skip-s3-cleanup: "true"
spec:
  legalEntity:
    name: "My Company"
    id: "12345"
  accountLink: ""
  aws:
    regions:
      - name: us-east-1
```

#### Patching an existing AccountClaim

```bash
kubectl annotate accountclaim my-account-claim \
  -n aws-account-operator \
  aws.managed.openshift.io/skip-s3-cleanup=true
```

### Removing the Annotation

If you want to re-enable S3 cleanup for future deletions:

```bash
kubectl annotate accountclaim my-account-claim \
  -n aws-account-operator \
  aws.managed.openshift.io/skip-s3-cleanup-
```

## Behavior

When the annotation is set to `"true"` (case-insensitive):

1. **During AccountClaim deletion**, the operator will:
   - ✅ Clean up EBS snapshots
   - ✅ Clean up EBS volumes
   - ✅ Clean up VPC endpoint service configurations
   - ✅ Clean up Route53 hosted zones
   - ❌ **SKIP** S3 bucket cleanup

2. **Logging**: The operator logs when S3 cleanup is skipped:
   ```
   Skipping S3 bucket cleanup due to annotation annotation=aws.managed.openshift.io/skip-s3-cleanup accountClaim=my-account-claim
   ```

3. **S3 buckets remain**: Any S3 buckets in the AWS account will **NOT** be deleted and must be cleaned up manually or via another process.

## Important Considerations

### ⚠️ Manual Cleanup Required

When you skip S3 cleanup, **you are responsible** for cleaning up S3 buckets manually or via another process. Orphaned S3 buckets can:
- Continue to incur AWS costs
- Consume AWS account quotas
- Pose security risks if they contain sensitive data

### 🔒 Account Reuse

If the account is being reused (returned to the pool):
- S3 buckets from the previous claim will remain
- The next AccountClaim assigned to this account will inherit these buckets
- This may cause naming conflicts or unexpected data access

### 💰 Cost Implications

S3 storage costs continue to accrue until buckets are deleted. Monitor your AWS billing for orphaned S3 resources.

## Example Workflow

### Scenario: Account with millions of S3 objects blocking cleanup

1. **Identify the slow AccountClaim**:
   ```bash
   # Find AccountClaims stuck in deletion
   kubectl get accountclaim -n aws-account-operator
   ```

2. **Add the skip annotation**:
   ```bash
   kubectl annotate accountclaim slow-claim \
     -n aws-account-operator \
     aws.managed.openshift.io/skip-s3-cleanup=true
   ```

3. **The operator will**:
   - Skip S3 cleanup on next reconciliation
   - Complete other cleanup operations (EBS, Route53, VPC)
   - Finalize the AccountClaim quickly

4. **Clean up S3 manually** (using AWS CLI or another process):
   ```bash
   # Assume role into the account
   aws sts assume-role --role-arn arn:aws:iam::ACCOUNT_ID:role/OrganizationAccountAccessRole --role-session-name cleanup

   # List and delete S3 buckets
   for bucket in $(aws s3api list-buckets --query 'Buckets[].Name' --output text); do
     echo "Deleting bucket: $bucket"
     aws s3 rb "s3://$bucket" --force
   done
   ```

## Complete Example

Here's a complete example of an AccountClaim with S3 cleanup skipped:

```yaml
---
# Example: AccountClaim with S3 cleanup skipped
# Use this when S3 cleanup is too slow or will be handled externally
apiVersion: aws.managed.openshift.io/v1alpha1
kind: AccountClaim
metadata:
  name: example-claim-skip-s3
  namespace: aws-account-operator
  annotations:
    # Skip S3 bucket cleanup during finalization
    # This speeds up AccountClaim deletion when there are many S3 objects
    aws.managed.openshift.io/skip-s3-cleanup: "true"
spec:
  legalEntity:
    name: "Example Corp"
    id: "example-123"
  accountLink: ""
  aws:
    regions:
      - name: us-east-1

---
# To patch an existing AccountClaim:
# kubectl annotate accountclaim <claim-name> \
#   -n aws-account-operator \
#   aws.managed.openshift.io/skip-s3-cleanup=true

---
# IMPORTANT: When using this annotation
#
# ✅ What gets cleaned up:
# - EBS snapshots
# - EBS volumes
# - VPC endpoint service configurations
# - Route53 hosted zones
#
# ❌ What does NOT get cleaned up:
# - S3 buckets and their contents
#
# You MUST clean up S3 buckets manually or via another process!
#
# Example manual cleanup:
# aws s3 ls --profile <account-profile>
# aws s3 rb s3://bucket-name --force --profile <account-profile>
```

## Implementation Details

- **Annotation Key**: `aws.managed.openshift.io/skip-s3-cleanup`
- **Valid Values**: `"true"`, `"True"`, `"TRUE"` (case-insensitive)
- **Invalid Values**: Any other value (including `"false"`) means S3 cleanup will run normally
- **Location**: Can be set in AccountClaim metadata annotations
- **Timing**: Checked during AccountClaim finalization (when the claim is deleted)
